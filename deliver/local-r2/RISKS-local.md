# RISKS-local: what can go wrong at home, ranked (local r2)

Ranked by cost to the combine first, likelihood second. "Alert" = what reaches Mac's phone without him looking. Open positions keep their broker-side stop and targets in every case below (BF-ALERTS.md); what is lost is management: the runner lock, the 13:10 PT flat step, new entries.

| # | Failure | What happens | Mitigation in the package | Alert that fires |
|---|---|---|---|---|
| 1 | **Two bots on one account** (server re-enabled, or its weekend-start timer left on) | Double orders on one account | `stop` disables every server unit, both weekend timers included; `start` needs an ssh proof (OFF and DISABLED, at most 10 min old); pre-start guard at every later start; `resume` needs the mirror proof; daily check line | None automatic. The daily check prints "THE SERVER'S PHONE SERVER ANSWERS". The guard only sees a server whose phone server is up and reachable |
| 2 | **Laptop sleeps** (Start > Sleep, lid on battery, Modern Standby, low battery) | Bot frozen; resumes on wake as if nothing happened; clock may lag | Sleep and hibernate off on AC, lid/buttons = do nothing on AC, read-back commands, "plugged in" rule; clock timer corrects and pushes "PC clock corrected" after the wake | **None while asleep.** With stage H: the outside alarm after 5 min. After the wake: the clock push (only if the clock lagged more than 2 s) |
| 3 | **Windows restart** (update, crash) | Hard kill mid-session; with automatic sign-in (stage E5) the bot is back about 3 minutes after Windows is up, **only if** sign-in, logon task, keep-alive and start guard all fire; otherwise down until Mac signs in | Automatic sign-in with its mandatory restart test (repeated after the lock step, every feature update, every password change); active hours; manual update on Saturday | **None if the chain fails** (outside alarm off by ruling). After a start: the bot's own "restarted" pushes only at 3 starts in 30 min |
| 3b | **Automatic sign-in itself** | Whoever opens or restarts the laptop is in Mac's Windows account; the stored password can be read by an administrator of the laptop | Laptop stays at home; optional, untested lock-after-sign-in task (E5.6); undo is one button | None |
| 4 | **WSL stops when idle, or the keep-alive window is closed, or `wsl --shutdown` / a WSL update** | Same as 3 without the reboot | `instanceIdleTimeout=-1` plus the open `wsl.exe` handle; the 10-minute test; "never close the black window"; `Restart` of the task at next logon | **None.** With stage H: the outside alarm |
| 5 | **Home internet down mid-trade** | Bot cannot poll or manage; pushes cannot leave | None possible on the laptop. Broker-side stop and targets hold. Phone on mobile data + TopstepX app to manage by hand | **None from the laptop.** With stage H: the outside alarm (the phone must be on mobile data to get it) |
| 6 | Bot process dead or frozen while the laptop is fine | No trading | `Restart=always` (unit); `mac-bot-watchdog.timer` added here (the server never ran the watchdog) | "Bot NOT RUNNING (no heartbeat)" after 10 min in trading hours; the in-bot "not LIVE 10+ min" and "restarted 2 times in 30 min" pushes as today |
| 7 | Clock drift after an unplanned sleep | Session windows, the 13:10 PT step, news blocks and the 60 s phone-request limit all read the clock | Three checks (start guard 5 s, every-minute timer 2 s, daily check 3 s against the internet) | "PC clock corrected" push when the timer fixes it |
| 8 | Laptop off across the weekend timers | Fixed in r2 (reviewer F1): on the PC the stop timer is not caught up, the start timer is. Left over: a laptop that is off at Friday 2 PM PT and on again before Sunday 3 PM keeps the bot running into the closed market until the start time passes (no trading is possible then) | Drop-in `Persistent=false` on the stop timer; first-Monday check in the sheet | Watchdog "Bot NOT RUNNING" in trading hours if the bot is in fact off |
| 9 | Windows update resets power settings, or `.wslconfig` gets a typo | Sleep returns; memory cap silently back to 3.9 GB | Read-back commands in stage E1 and `free -m` in B4; rerun after every feature update | None. Shows up as failure 2 |
| 10 | Disk fills (journal about 100 MB and growing, daily logs, each installer backs up the whole 322 MB folder) | Bot cannot write state; installers refuse | `check` STOPs under 5 GB free; installers already keep 1 GB free | None automatic |
| 11 | Antivirus scans the WSL disk file or blocks `wsl.exe` / Node | Slow start, or WSL blocked | Leave Windows Security on, no exclusions by default; if a third-party suite is installed, test stage B6 with it running | None. Shows up as failure 4 or 6 |
| 12 | Phone server reachable without the key (a forwarder that delivers from loopback: `tailscale serve`, portproxy to 127.0.0.1) | Anyone who reaches the forwarder can flatten, pause and relay broker calls | Default has no forwarder; D1 uses mirrored mode (the phone's own address arrives); `check` tests 401 from a non-loopback address; the sheet's no-key test on the phone | None |
| 13 | Undo after the PC bot has traded | The server restarts from the journal and state of the move day | OPEN ITEM "copy-back", named in sheet G3; not built | None |
| 13b | Something started on the server by hand, or an old server sheet run (reviewer F9) | Two bots; the server has no guard | Sheet rule at C9 (all old server sheets void); the PC sees it only at its next start or daily check, and only if the server's phone port answers | None |
| 13c | Server cancelled with its address still stored (reviewer F10) | A stranger's machine on that address blocks every PC start | Sheet C9: `mac-local vps-address none` first | Watchdog "Bot NOT RUNNING" |
| 13d | A web page open in a browser on the laptop calls `localhost:8787` (reviewer F12) | It could send flatten or pause without the key | Sheet stage F: no casual browsing on the trading laptop in a session | None |
| 14 | Memory: 3 GB cap with both services allowed 1024 MB each | Tight only if both hit their limit together | 2 GB swap; measured 325 MB peak for the bot at start with the 98.7 MB journal | In-bot restart pushes if it crash-loops |
| 15 | `NTFY_TOPIC` missing from the env file | Every push silently does nothing | `check bot` and `start` STOP when the name is absent | None by nature |

## Not solved by this package
- Rows 2 to 5 have no alert: stage H is off by Mac's ruling until Topstep answers. That is stated in bold at the top of the sheet.
- Copy-back for an undo after the PC bot has traded (row 13).
- Whether Topstep accepts a phone page over Wi-Fi, Tailscale, or the alive ping: Mac's question to Topstep.
